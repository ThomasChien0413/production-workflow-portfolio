# Security and publication boundaries

This is a local portfolio demonstration. Default credentials are intentionally public and unsuitable for a deployed service. Do not connect it to real company databases, storage, push subscriptions, accounts or deployment credentials.

The publication audit checks selected filename/content patterns and reports only paths/rules/line numbers, never matched credentials. It is **not** proof that every possible secret or confidential fact has been detected. Manually review staged changes, images, embedded diagram assets, dependency notices and GitHub settings before making the repository public. Original history is intentionally absent, not retrospectively certified secret-free.

All supplied sheet layouts and letterheads are shared with owner permission. Real saved orders, employee records and operational details are not included. Test values must remain synthetic. Do not upload database dumps, traces, browser storage states, local `.env` files or operational screenshots in issues or PRs.

CI has a read-only token and uses GitHub-hosted runners only. No company self-hosted runner, deployment workflow, privileged PR trigger, secrets or cloud integration is configured. Private-stage jobs are intentionally skipped. Review Actions logs before public visibility; visibility changes cannot retrieve copies already downloaded.

To report a vulnerability, contact the repository owner privately through GitHub rather than posting exploit credentials or confidential data in a public issue. Do not test against any company service.
